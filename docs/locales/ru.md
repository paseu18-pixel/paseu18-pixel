# Матео Силва-Карвалью (Mateo Silva-Carvalho)

**Инженер распределенных хранилищ и внутреннего устройства СУБД | Системный ремесленник**  
*Флорианополис, Бразилия | UTC-3*

> *«Дисковый ввод-вывод — это место преступления. Усиление записи (Write Amplification) — виновник. B-деревья и LSM-деревья — прямые улики.»*

Я проектирую и создаю высокопроизводительные движки хранения баз данных, журналы предзаписи (WAL) только для добавления (append-only) и инфраструктуру распределенного консенсуса. Моя повседневная работа сосредоточена на низкоуровневом системном программировании для Linux, асинхронном вводе-выводе в обход ядра (`io_uring`), структурах данных с отображением в память и параллельных постраничных кэшах без блокировок (lock-free) на современных Go, C++20 и Zig.

Вне терминала я обжариваю бразильский спешелти-кофе одного происхождения (Catuaí и Yellow Bourbon), занимаюсь виндсерфингом на атлантических волнах побережья Санта-Катарины и вручную паяю кастомные раздельные эргономичные механические клавиатуры.

## Области экспертизы и ключевые направления

- **Движки хранения СУБД**: Проектирование многоуровневых (leveled) и ярусных (tiered) деревьев LSM (Log-Structured Merge), безаллокационного WAL с адаптивным групповым коммитом и алгоритмов вытеснения блочного кэша (W-TinyLFU, 2Q, Clock-Pro).
- **Асинхронный ввод-вывод и Kernel-Bypass**: Предельное насыщение пропускной способности NVMe SSD через Linux `io_uring` с зарегистрированными буферами (`IORING_REGISTER_BUFFERS`), соединение сокетов без копирования (`splice`) и прямой блочный обмен с выравниванием (`O_DIRECT`).
- **Распределенный консенсус**: Реализация конечных автоматов Multi-Raft, компактификация журналов на векторных часах и детерминированная проверка аварийного восстановления путем симуляции сетевых разделений и инъекции сбоев.
- **Структуры данных с учетом кэша**: Разработка неблокирующих списков с пропусками (skip lists), адаптивных префиксных деревьев (ART), деревьев B+ с выравниванием по строкам кэша и безопасных арена-аллокаторов памяти.

## Избранные проекты с открытым исходным кодом

### [ouroboros-kv](https://github.com/mateo-silva/ouroboros-kv)
*Встраиваемый неблокирующий LSM-движок хранения на Go с путями чтения без аллокаций памяти.*
- Параллельные memtables на базе неблокирующих списков с пропусками и выравниванием узлов по строкам кэша.
- Адаптивная ярусная компактификация, созданная специально для снижения коэффициента усиления записи на NVMe.
- Блочные SIMD-фильтры Блума, снижающие уровень ложноположительных срабатываний ниже 0,8 % без аллокаций в куче.
- Гарантированное восстановление после сбоев благодаря WAL только для добавления с контрольными суммами crc32c.

### [ring-fs](https://github.com/mateo-silva/ring-fs)
*Высокопроизводительный движок хранения только для добавления в пространстве пользователя на Zig поверх нативного `io_uring`.*
- Работает исключительно на предварительно зарегистрированных буферах (`IORING_REGISTER_BUFFERS`) и потоках поллинга ядра (SQPOLL).
- Обеспечивает свыше 820 000 устойчивых последовательных IOPS записи на потребительских NVMe-накопителях PCIe 4.0.
- Менеджер страничного кэша в пространстве пользователя с детерминированным выравниванием по страницам 4 КБ.

### [paxos-forge](https://github.com/mateo-silva/paxos-forge)
*Детерминированный симуляционный стенд для распределенных автоматов консенсуса.*
- Проверяет движки репликации журналов в условиях эмулируемых асинхронных сетевых сбоев, потерь пакетов и дрейфа таймеров.
- Запускает тысячи виртуальных узлов в одном процессе с дискретным виртуальным шагом времени для 100% воспроизводимости багов.
- Успешно проверены переходы состояний на эталонных реализациях Raft и Multi-Paxos.

### [vfs-spdk](https://github.com/mateo-silva/vfs-spdk)
*Экспериментальный драйвер Virtual File System (VFS) для SQLite, направляющий запросы напрямую на NVMe SSD.*
- Исключает накладные расходы файловой системы ОС за счет прямой записи в блочные диапазоны через SPDK.
- Снижает задержку фиксации транзакций на 99-м процентиле (p99) на 42% при высоких нагрузках.

## Инварианты разработки хранилищ (Кодекс чести)

При реализации низкоуровневых компонентов хранения эти четыре правила соблюдаются непререкаемо:

```
[Механические инварианты движка хранения]
├── 1. Надежность (Durability) не подлежит компромиссам
│   └── Никогда не возвращать подтверждение клиенту до полного завершения барьера fsync / fdatasync.
├── 2. Строгое выравнивание памяти и строк кэша
│   └── Все дисковые структуры страниц должны быть жестко выровнены по границе 4096 байт (безопасно для O_DIRECT).
├── 3. Полное устранение борьбы за блокировки на горячих путях
│   └── Пути чтения и добавления должны оставаться абсолютно неблокирующими за счет атомарных CAS и указателей.
└── 4. Проверка устойчивости в экстремальных условиях
    └── Движок хранения готов к эксплуатации только тогда, когда он доказал выживаемость при внезапном сбое питания.
```
